# C12 — Recursive Improvement Lab

DGM, HGM, HyperAgents and similar methods are research candidates inside an isolated laboratory, never a free-running production loop.

Each tournament fixes immutable champion and evaluator snapshots. Candidate generators receive an allowlisted editable surface in isolated worktrees/containers without hidden holdouts, production writes, broker credentials, active Risk Kernel or canon mutation.

Candidates undergo unit, property, security, performance and financial evaluation. The archive retains lineage and rejected candidates to preserve diversity and prevent repeated failures. Reward hacking, test deletion, evaluator mutation, secret access and metric gaming are explicit adversarial cases.

The output is an improvement proposal with diff, evidence, minority report, rollback and canary plan. It cannot deploy itself or promote the champion. Initial human approval and normal MARKET-OS gates remain mandatory.
